# ThirdSpace 控制面契约统一设计

## 背景

ThirdSpace 的目录骨架已经基本完整，但 Schema、`WORKSPACE.md`、Skill 索引和审计器对 type、status、项目字段、报告路径与 LifeOS 写入边界的定义不一致。当前审计主要检查文件和目录是否存在，无法阻止语义契约漂移。

## 目标

1. `.thirdspace/schema/` 成为唯一机器可读事实源。
2. 工作区规范与 Skill 只使用 Schema 允许的 type、status 和扩展字段。
3. `audit-subsystems` 同时检查结构存在性与契约语义一致性。
4. 新 vault 初始化结果与 canonical vault 的 Schema、目录和初始数据完全一致。

## 非目标

- 不迁移或重写用户知识内容。
- 不新增仓库内不存在的领域 Skill。
- 不引入 YAML 依赖包、数据库或向量检索。
- 不恢复 `project-taxonomy.yaml` 或 `00-系统/Schema/` 等第二事实源。

## Canonical Schema

### type

`taxonomy.yaml` 的全局 type 并集为：

```text
note, card, article, voiceover, script, deck,
review, reflection, worklog, clipping, study,
spec, skill, roadmap, board, event, project, resource
```

领域细分不再膨胀全局 type：

- 人际原始记录：`type: event` + `record_kind: raw`
- 普通人际事件：`type: event` + `record_kind: analyzed`
- 资产、工作流和人物数据：`type: resource` + `resource_kind`

### status

`frontmatter.yaml` 的全局 status 并集为：

```text
draft, active, processed, review, published, archived
```

输出生命周期统一为：

```text
draft -> review -> published -> archived
```

`ready` 不再作为合法 status。

### 条件扩展字段

`frontmatter.yaml` 新增 `conditional_fields`，但全局必填 9 字段不变。

`type: project` 的核心项目文档必须包含：

```yaml
project: "项目名"
project_type: "content|product|operations|business|research|experiment"
project_category: "内容创作|产品系统|运营增长|商业合作|研究验证|实验原型"
stage: "idea|research|prototype|active|paused|completed|archived"
```

`type: resource` 可使用：

```yaml
resource_kind: "reference|asset|workflow|profile"
```

`type: event` 可使用：

```yaml
record_kind: "raw|analyzed"
```

## 工作区契约

| 工作区 | allowed_types | status_machine |
|---|---|---|
| `00-系统` | `spec, skill, roadmap, note, review` | `draft, active, archived` |
| `01-收件箱` | `note, clipping, card` | `draft, active, processed, archived` |
| `02-日记` | `worklog, reflection, review, event, note` | `draft, active, archived` |
| `03-知识` | `note, card, study, spec, skill, roadmap` | `draft, active, archived` |
| `04-项目` | `project, roadmap, spec, board, note` | `draft, active, archived` |
| `05-资源` | `resource, note` | `active, archived` |
| `06-输出` | `article, voiceover, script, deck, review` | `draft, review, published, archived` |
| `99-归档` | `any` | `archived` |

`05-资源` 设为 `agent_writable: true`，但 Agent 只能在用户意图命中或 LifeOS 同步中写入索引和人物档案；附件和二进制资产导入仍需明确授权。

## 控制面目录

- `.thirdspace/schema/`：唯一 Schema 事实源。
- `.thirdspace/reports/`：本机生成的审计报告，不共享。
- `.thirdspace/queues/`：本机处理队列，不共享。
- `.thirdspace/manifests/`：迁移执行记录。
- `00-系统/Agent/`：Agent 入口说明，必须包含 `README.md`。
- `00-系统/Skills/`：canonical Skill 及内部实现。
- `00-系统/运行时/`：Hook、crontab 和自动化规格。
- `00-系统/规范/`：人类可读的上位协议。

删除空目录 `00-系统/Schema/` 和 `00-系统/审计/`。需要长期保留的审计结论应转化为 `00-系统/规范/` 下的正式规范或决策文档，而不复制生成报告。

## LifeOS 数据

canonical 人物结构为：

```json
{
  "version": "1.0",
  "people": []
}
```

初始化应同时创建：

- `05-资源/人物档案/people.json`
- `.thirdspace/data/lifeos/people.json`

任何人物更新必须在同一次操作中更新两份文件。两份内容不一致时，审计报错且不自动选择覆盖方向。

## Skill 索引与路由

仓库内领域 Skill 以实际存在的 canonical 目录为准：

- `knowledge`
- `lifeos`
- `reflect`
- `review`
- `worklog`

`workspace-tools.yaml` 路由为：

- `02-日记`：`worklog`、`lifeos`、`reflect`、`review`
- `03-知识`：`knowledge`
- 其他工作区：暂无领域 Skill

Skill 索引不再列出仓库内不存在的领域 Skill。

## 审计设计

`audit-subsystems` 在现有结构检查之上新增：

1. `subsystems.yaml.allowed_types` 必须全部存在于 `taxonomy.yaml.type_values`，`any` 除外。
2. `subsystems.yaml.status_machine` 必须全部存在于 `frontmatter.yaml.status_values`。
3. `workspace-tools.yaml` 中每个 primary/domain Skill 必须存在于 `00-系统/Skills/<skill>/SKILL.md`。
4. 内容 Markdown 的 `type`、`status`、`workspace` 必须合法，并符合所在工作区契约。
5. `type: project` 的核心文档检查项目扩展字段与枚举。
6. `type: resource|event` 出现扩展字段时，检查扩展枚举。
7. LifeOS 两份 `people.json` 必须存在、JSON 有效且内容一致。
8. `00-系统/Agent/README.md` 必须存在。

`WORKSPACE.md`、`AGENTS.md`、`CLAUDE.md`、`README.md` 和 `SKILL.md` 是控制文档，明确豁免内容 Frontmatter 审计。`04-项目/WORKSPACE.md` 删除损坏的局部 Frontmatter，与其他工作区保持一致。

## 实现与测试边界

- 使用 Node.js 内置模块，不新增运行时依赖。
- 为每类契约漂移先写失败的回归测试。
- 测试使用临时 vault fixture，不修改用户内容。
- `test-init.sh` 必须在临时目录完成测试，不修改全局 Git 配置。

## 验收标准

1. Node 回归测试全部通过。
2. `test-init.sh` 全部通过。
3. `audit-system`、`audit-workspaces`、`audit-subsystems`、`audit-skill-locations` 均为零 error、零 warning。
4. 新初始化 vault 只包含五份 canonical Schema，且 LifeOS 双副本存在并一致。
5. 除本设计文档的迁移说明外，`rg` 不再发现其他活跃规范引用 `project-taxonomy.yaml`、`event-raw`、`profile-data` 或 `status: ready`。
