# 项目工作区目录规范

## 目标

`04-项目` 不预设分类目录；每个项目直接建立一级目录并自行维护说明。项目归属、阶段与领域维度由项目自身文档（`brief.md`、`AGENTS.md`、`CLAUDE.md`）和 Frontmatter 表达，不再通过目录层级表达。

## 目录约定

```text
04-项目/YYYYMMDDHHMM_项目名/
```

- 项目目录使用 `YYYYMMDDHHMM_项目名/`。
- 历史项目目录若只有日期没有时分，可先保留，后续重命名必须通过审计和迁移 trace。
- 项目内文档可使用 `brief.md`、`plan.md`、`assets.md`、`review.md`。
- 复杂项目允许保留 `_assets/`、`_template/`、`research/`、`renders/` 等内部结构；这些目录属于项目运行上下文，不按全库一层目录规则强制打散。
- 旧 prompt 入口不得留在项目资产中，必须迁入 Skill references 或归档。

## Frontmatter 字段

项目字段的机器可读事实源为 `.thirdspace/schema/frontmatter.yaml` 中的 `conditional_fields.project`。

项目入口文档或项目内核心文档应包含：

```yaml
workspace: "04-项目"
type: "project"
project: "项目名"
stage: "idea|research|prototype|active|paused|completed|archived"
status: "active"
```

`project_type` / `project_category` 不再作为枚举约束；项目维度（研究方向、领域等）自行写入 `tags` 或项目内说明文档。

## 原则

- 项目目录由主人自建并自管说明，Agent 不预设分类目录。
- 一个项目对应一个一级目录。
- 复杂项目内部结构不打散，例如 `_assets/`、`research/`、`renders/`、`.codex/skills/`。
- 跨目录移动必须写入迁移 trace，包含原路径、目标路径、判断理由、时间。
- 完结项目进入 `99-归档/完结项目`，并保留项目 trace。

## 审计

- `audit-projects` 只做项目名/结构规范建议，不做分类迁移。
- 建议目标路径直接为 `04-项目/YYYYMMDDHHMM_项目名`。
- `confidence >= 0.8` 的建议可进入待执行清单；`< 0.8` 必须人工确认。
